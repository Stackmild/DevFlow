系统结构

Cowork 负责宿主执行；DevFlow 负责协议、状态机、门禁、skill 调度。

Cowork 宿主

  • 用户输入 @dev-orchestrator
  • Agent tool spawn
  • PreToolUse / PostToolUse / UserPromptSubmit hook
→

DevFlow 控制层

  • devflow-enforcer.mjs 拦截工具调用
  • devflow-gate.mjs 执行 9 个 action
  • verify_state 做 D1-D7 对账
→

任务状态与项目产出

  • orchestrator-state/{task_id}/ 保存事实
  • project_path 保存业务代码和 docs
  • sub-agent 通过 handoff packet 获取输入

主控 Agent

dev-orchestrator 负责 phase 编排、Gate 展示、sub-skill 调度、state store 更新。v6.1 已完成协议同步，但行数仍 499，暂不瘦身。

专业 Skill

PM、architect、backend、frontend、FSD、reviewer、auditor 等专业 skill 执行具体判断和产出。10 个已完成瘦身和 pilot。

硬证据链

每次关键行为都要留下 permit、event、artifact 或 decision。后续 Gate 和 auditor 反查证据，避免“流程嘴上跑完”。

完整工作流

canonical phase：phase_a / phase_b / phase_c / phase_d_1 / phase_d_2 / phase_d_3 / phase_f。

phase_a 定义与初始化

第一步必须由 bootstrap 创建任务状态层，写入 protocol_version: 2、project_path、devflow_root、started_at、module_slug。

  • 识别内部/外部 repo
  • 创建 state store 子目录
  • 写首条 task_initialized 事件和 bootstrap permit
Action bootstrap transition phase_a → phase_b
phase_b 产品分析

调度 @product-manager，输出 task brief、product spec、routing decision。Gate 1 确认方向。

  • 明确问题、目标、范围、非目标
  • 判断是否需要设计、代码、handoff
  • Gate 1：GO / ADJUST / DEFER-TASK / PAUSE
Gate 1 dispatch_skill product-manager present_gate --gate 1
phase_c 设计阶段

按需调度 architect、backend、interaction、frontend。bugfix/hotfix 可合法跳过，但必须写 skip 决策。Gate 2 确认 scope 与架构。

  • @web-app-architect 输出 architecture-spec
  • @backend-data-api 输出 backend-contract
  • @webapp-interaction-designer 输出 interaction-spec
  • @frontend-design 输出 design-spec / package
Gate 2 routing-decision-C.yaml 缺 design dispatch permit 会 BLOCK
phase_d_1 执行实现

调度 @full-stack-developer，严格按 implementation-scope 和上游 contract 写代码，输出 change-package。

  • FSD 不自改 scope
  • 必须输出 scope_flags、completion_status 等契约字段
  • 涉及宿主/云端边界时输出 verification_boundary
D.1 dispatch_skill full-stack-developer transition phase_d_1 → phase_d_2
phase_d_2 独立审查

调度 @code-reviewer，按 scope_flags 条件追加一致性审计、Playwright E2E、发布前测试审查等。审查不能由 orchestrator 自审。

  • review report 是 Gate 3 前置证据
  • scope_flags.ui=true 或 scope_flags.interaction=true 时，D.2 reviewer set 包含 code-reviewer、webapp-consistency-audit、playwright-e2e-testing
  • playwright-e2e-testing 目标：交互路径、浏览器行为、关键 UI flow、视觉/交互回归证据
  • 测试/发布风险可追加 @pre-release-test-reviewer
D.2 reviewer dispatch permit 必须存在 transition phase_d_2 → phase_d_3
phase_d_3 验收准备

汇总 change-package、review-report、风险、验证边界。必须先 transition 到 phase_d_3，再写 Gate 3 决策，避免时间戳倒置。

  • Gate 3：ACCEPT / REVISE / PAUSE
  • ACCEPT 是唯一合法进入 Phase F 的路径
  • REVISE 走 continuation protocol
Gate 3 present_gate --gate 3 transition phase_d_3 → phase_f
phase_f 收尾

可调度 @state-auditor 做完整审计，回填 known gaps、roadmap、deferred。最后由 complete_task 原子写回 status: completed。

  • closeout 前必须通过 Gate 3、Phase D/F events、open blocker、permit/event 一致性检查
  • 成功后写 completed_at
Closeout verify_state complete_task

devflow-gate v6.1：9 个 Action

每个 action 都产出 ALLOW/BLOCK，并在允许时写 permit。新任务中 permit 是硬证据，不是可选日志。

Action 触发点 防什么 关键输出
bootstrap 任务第一步 任务未初始化、缺 project_path、缺协议版本 task.yaml、首条 event、bootstrap permit、目录结构
enter_phase 进入新 phase 前 跳 phase、缺前置 artifact enter phase permit
dispatch_skill 构造 handoff 或 dispatch 前 无 scope、无 change-package、无上游输入就调 sub-agent dispatch prerequisite 结果
present_gate 展示 Gate 1/2/3 前 跳过 pre-gate self-check、缺上游 dispatch permit present gate permit、gate decision event
transition phase 切换时 手写 phase events、events/task.yaml 漂移 phase_completed + phase_entered + snapshot 更新
post_gate3_write Gate 3 ACCEPT 后写文件前 Gate 3 后继续 ad-hoc 改代码 ALLOW/BLOCK
complete_task closeout 最后一步 假完成、缺 Gate 3、缺 Phase F、open blocker 未关 status: completed、completed_at
verify_state 每个非 bootstrap action 前 D1-D7 状态机异常 critical issue BLOCK，warnings 记录
finalize_dispatches gate action 前自动执行 Cowork 不触发 PostToolUse，dispatch 卡在 authorized dispatch_skill-* permit、skill_dispatched event

Enforcer：Hook 自动执行层

enforcer 负责拦工具调用，把“应该调用 gate”变成“绕不过 gate”。

Hook 注册

  • PreToolUse matcher：Write|Edit|MultiEdit|Task
  • PostToolUse matcher：Task
  • UserPromptSubmit：状态一致性和上下文提醒
  • 重复 hook 通过 5 秒窗口去重，避免 user/project 双层重复警告

关键 DENY

  • 新任务 Task spawn 缺 task_id 或 handoff_id
  • handoff packet 不存在、skill 不匹配、input artifact hash/size 错
  • 手写 phase_completed / phase_entered
  • 直接编辑 task.yaml.current_phase
  • Gate 3 后无 continuation 写项目代码

Task Spawn Handoff 协议

Cowork 的 Agent runtime type 与 DevFlow skill 名不是一回事。正确调用方式：

Task tool:
  subagenttype: "claude"
  prompt:
    @full-stack-developer
    task_id: micro-test-001
    handoff_id: handoff-D1-fsd-001
阶段 证据 语义
PreToolUse dispatch_authorized-{skill}-{auth_id}.json + skill_dispatch_authorized 只代表“允许发起”，不代表 sub-agent 成功执行。
PostToolUse 或 fallback dispatch_skill-{skill}-{handoff_id}-{sha}.json + skill_dispatched 代表 dispatch finalized，可被 Gate 和 verify_state 采信。
Input 校验 declared_size / declared_hash / large_file_reason 防止 sub-agent 收到不存在或错误输入后编结果。

State Store：任务事实层

业务产出可在项目 repo；状态事实必须在 taskdir。v6.1 的核心修复就是把两者重新绑定。

目录结构

orchestrator-state/{task_id}/
├── task.yaml
├── events.jsonl
├── artifacts/
├── decisions/
├── handoffs/
│   └── {handoff_id}.yaml
├── issues/
├── monitor/
│   └── audit-incremental-{phase}-{seq}.yaml
├── .permits/
└── .journal/

写入规则

  • phase event 只能由 transition 写入。
  • transition 在 lock 内追加 events，再原子更新 task snapshot。
  • 普通 artifact/decision 先落事实，再更新 snapshot。
  • journal 残留可由 verify_state --repairable 判断 commit/rollback。

verify_state D1-D7

编号 检测项 拦截价值
D1 current_phase=phase_a 但业务 specs 已大量存在 抓“业务推进、状态机停摆”。
D2 Gate decision 缺失但 handoff summary 存在 抓 Gate 决策未落盘。
D3 events 长时间无更新且任务未暂停 抓僵死任务或漏写 event。
D4 skill_dispatch_authorized 长期未 finalized 抓 PostToolUse 缺口或 spawn 失败。
D5 自宣称合规但缺 handoff/permit 证据 抓“嘴上遵守，状态无证据”。
D6 dispatch permit 数与 skill_dispatched event 数不一致 抓内部证据链断裂。
D7 task.yaml.current_phase 与最新 phase_entered 不一致 抓 snapshot drift 或手写篡改。

Incremental Auditor

incremental-auditor.mjs 在 phase_completed 后后台触发，跑 10 项轻量检查：events 可解析性、snapshot drift、dispatch residue、permit/event 一致性、Gate decision 一致性、handoff 数量、open blocker、必需 artifact、completed closeout、manual bypass。非阻塞，写入 monitor/audit-incremental-*.yaml。

日常运行与验证

  • 第一步是否写出 bootstrap permit

  • project_path 是否指向真实项目 repo
  • sub-agent prompt 是否含 task_id + handoff_id + @skill
  • Gate 前是否自动 finalize pending dispatch

真实任务观察文件

  • monitor/task-spawn-samples.jsonl
  • monitor/audit-incremental-*.yaml

  • artifacts/e2e-visual-test-report.yaml 是否在 UI/interaction 任务中存在
